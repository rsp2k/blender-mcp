24 first-class MCP tools, all `blender_`-prefixed, that wrap the addon's `@command` handlers. The LLM calls them like any MCP tool; the server registers a Future via JobWaiter, routes a `command_dispatch` payload through the bus to a Blender peer, awaits the addon's `blender_job_update` reply, and returns the result synchronously. The bus round-trip is invisible from the caller's perspective.

Choose dispatch tools over [`blender_send_message`](/reference/bus-tools/) + script-dispatch unless you need arbitrary Python. See [Command dispatch vs script dispatch](/explanation/dispatch-vs-script/) for the decision tree.

## Common parameters

Every dispatch tool accepts the same two infrastructure parameters in addition to its own:

| Parameter | Default | Purpose |
|---|---|---|
| `target_uuid` | `None` | A Blender client UUID, `"latest"` (newest registration among live clients) or `"pid:<n>"`. If omitted and exactly one live Blender peer is connected, that one is used. Peers with no heartbeat for `BLENDER_MCP_CLIENT_STALE_SECONDS` (default 180) don't count. Otherwise returns `ambiguous_target`, `no_live_client` or `no_client`. |
| `_timeout` | varies | Seconds to wait for the addon's reply. Underscore-prefixed so it doesn't leak into the addon-side `params` dict. |

Tools also receive a `ctx: Context` injected by FastMCP for auth.

## Return envelope

Every dispatch tool returns a JSON string with this shape:

```json
{
  "status": "completed" | "failed" | "queued" | "running" | "timeout" | "no_client" | "ambiguous_target" | "unknown_target",
  "command": "<command name>",
  "target_uuid": "<chosen client>",
  "job_id": "j-<12 hex>",
  "result": <inner JSON>,
  "error": "<message or empty>"
}
```

| Status | Meaning |
|---|---|
| `completed` | Addon handler returned successfully; `result` holds its output |
| `failed` | Addon handler raised; `error` holds the message |
| `queued` / `running` | `_timeout` elapsed but the job is still waiting or still running in Blender. It keeps going and its result is kept; poll it with `job_id` (see [Long-running jobs](/how-to/long-running-jobs/)) |
| `timeout` | `_timeout` elapsed without an addon reply and the job store was unavailable, so there is no `job_id` to follow |
| `no_client` | No Blender peer on the user's bus could be targeted |
| `ambiguous_target` | Multiple Blender peers, no `target_uuid` to disambiguate |
| `no_live_client` | Several Blender peers are registered but none has heartbeated recently; `candidates` lists them |
| `unknown_target` | `target_uuid` was set but no matching client is registered |

## Tier 1: always-on core (7)

Foundational tools. No gating; always available when at least one Blender peer is connected.

### `blender_get_scene_info`

```python
blender_get_scene_info(target_uuid: str | None = None, _timeout: float = 30) -> str
```

Snapshot of the active scene: name, object count, first ~10 objects, materials count.

### `blender_get_object_info`

```python
blender_get_object_info(name: str, target_uuid: str | None = None, _timeout: float = 30) -> str
```

Detailed descriptor for a specific object by name: transform, mesh stats, material slots. Returns `failed` if `name` doesn't exist.

### `blender_browse_data`

```python
blender_browse_data(
    collection: str | None = None,
    item_name: str | None = None,
    page: int = 1,
    page_size: int = 50,
    detail_level: str = "summary",
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

Paginated `bpy.data.*` browser. Pass `collection="objects"`, `"materials"`, `"meshes"`, etc. Omit `collection` to list available collections. Pass `item_name` to drill into a single item. `detail_level` is `summary` or `full`.

### `blender_execute_code`

```python
blender_execute_code(code: str, target_uuid: str | None = None, _timeout: float = 60) -> str
```

Execute arbitrary Python in the Blender main thread. Captures stdout and returns it as `result`. The script's globals include `bpy`, `bmesh`, `mathutils`. Use this when no dedicated dispatch tool exists for the operation; for multi-step orchestration in a single round-trip, see [`blender_send_message`](/reference/bus-tools/) with a `job_dispatch` payload.

### `blender_get_viewport_screenshot`

```python
blender_get_viewport_screenshot(
    filepath: str,
    max_size: int = 0,
    format: str = "png",
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

Save a 3D viewport screenshot to `filepath` on the Blender host. `max_size` caps the longest edge in pixels; `0` (the default) keeps the viewport's native resolution. `format` is `png` or `jpg`.

### `blender_get_console_output`

```python
blender_get_console_output(
    level: str = "all",
    page: int = 1,
    page_size: int = 50,
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

Paginated scrape of the Blender console. `level` filters lines by kind: `all`, `info`, `warning`, `error`, `output`. Also exposed as a resource — see [`blender://console/{level}`](/reference/resources/).

### `blender_console_operations`

```python
blender_console_operations(
    operation: str = "get_info",
    params: dict | None = None,
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

Invoke a `bpy.ops.console.*` operator (e.g. `execute`, `autocomplete`, `clear`). See the addon's `console_operations` handler for the operation catalog.

## Annotations (5)

Read what the user drew with Blender's annotation tool (D-key and drag), and draw marks of your own to point things out. Blender 5.x keeps these strokes in `bpy.data.annotations`; the scene's annotation datablock holds one or more layers.

Write tools draw on their own layer, `LLM` by default, created orange and slightly thicker than the user's default so the two are easy to tell apart. The user's layers are never changed unless you name one. Strokes you draw read back through `blender_list_annotations` and `blender_get_annotation` like anything the user drew.

### `blender_list_annotations`

```python
blender_list_annotations(include_bbox: bool = True, limit: int = 200, target_uuid: str | None = None, _timeout: float = 30) -> str
```

Every stroke with its id, layer, point count, colour, coordinate `space` and, for 3D strokes, a world-space bounding box. Cheap: no point coordinates.

### `blender_get_annotation`

```python
blender_get_annotation(annotation_id: str, target_uuid: str | None = None, _timeout: float = 30) -> str
```

Full geometry for one stroke. `world_points` is filled only for `space: "3D"`; view-space strokes return `raw_points` in viewport-percentage units and report their space as `2D-Local`.

### `blender_add_annotation_stroke`

```python
blender_add_annotation_stroke(points: list[list[float]], layer: str = "LLM", color: list[float] | None = None, thickness: int | None = None, space: str = "3D", cyclic: bool = False, target_uuid: str | None = None, _timeout: float = 30) -> str
```

Draw one stroke. With `space="3D"`, `points` are world coordinates `[x, y, z]` and the mark sits in the scene. With `space="view"`, points are `[x, y]` percentages of the viewport region (0 to 100, origin bottom-left) and the mark stays fixed on screen. `color` (`[r, g, b]`, 0 to 1) and `thickness` (1 to 10) apply to the whole layer, because Blender stores them per layer; use another layer name for another colour. `cyclic` closes the stroke. Returns the stroke `id`.

Arguments are checked before anything is sent to Blender: fewer than two points, wrong point shapes, colours outside 0 to 1 or thickness outside 1 to 10 return `invalid_argument` immediately.

### `blender_annotate_object`

```python
blender_annotate_object(object: str, style: str = "box", label: str | None = None, layer: str = "LLM", color: list[float] | None = None, thickness: int | None = None, padding: float = 0.05, target_uuid: str | None = None, _timeout: float = 30) -> str
```

Mark an object so the user can see which one you mean. `box` outlines its world-space bounding box (six strokes), `circle` rings it at mid height, `arrow` comes down at an angle and stops just above its top. `padding` grows the outline by that fraction of the object's largest side. Annotations can't hold text, so `label` is echoed back with `label_drawn: false`; put it in your reply instead.

### `blender_clear_annotations`

```python
blender_clear_annotations(layer: str = "LLM", target_uuid: str | None = None, _timeout: float = 30) -> str
```

Remove every stroke on one layer and report how many. Other layers are untouched and the layer itself is kept. A missing layer returns `found: false`, not an error.

Marks are drawn on the layer's earliest frame so they stay visible while the timeline moves, and the annotation overlay is switched on in every 3D viewport.

## Assembly analysis and keyframes (5, ungated)

For physical assemblies and keyframed configurations, where bounding boxes overlap far more often than parts actually intersect, and where Blender 5.x removed `action.fcurves`. Every tool evaluates the scene as shown (modifiers, animation), and any `frame` argument puts the scene back on its original frame afterwards.

### `blender_check_interference`

```python
blender_check_interference(
    objects: list[str] | str | None = None,   # None = visible geometry, "all" includes hidden
    frame: int | None = None,
    frames: list[int] | None = None,          # sweep up to 50 frames
    ignore_pairs: list[list[str]] | None = None,
    include_hidden: bool = False,
    tolerance: float = 0.0,
    check_containment: bool = True,
    sample_points: int = 3,
    target_uuid: str | None = None,
    _timeout: float = 60,
) -> str
```

Tests every pair whose world bounds overlap for real triangle intersection on evaluated, world-space meshes. Returns `intersecting` pairs with a `triangle_pairs` count and sample points, `contained` pairs (a part entirely inside another crosses no triangles, so it's found by an inside test that needs closed meshes with outward normals), and `bbox_overlap_pairs` so you can see how many box overlaps were false alarms. Faces that only touch coplanar don't count as intersecting; raise `tolerance` (scene units) to catch near or touching contact. Use `ignore_pairs` for intended contact such as snap fits. Up to 300 objects per call; a long sweep comes back as a job to follow with `blender_job_status`.

### `blender_world_bounds`

```python
blender_world_bounds(
    objects: list[str] | str | None = None,
    frame: int | None = None,
    include_hidden: bool = False,
    exact: bool = False,
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

World-space `min`, `max`, `size` and `center` per object, plus their `union`. The default transforms the evaluated local bound box, which never under-reports but can over-report for rotated parts; `exact=True` uses evaluated vertices for tight bounds.

### `blender_get_keyframes`

```python
blender_get_keyframes(object: str, data_path: str | None = None, owner: str = "object",
                      target_uuid: str | None = None, _timeout: float = 30) -> str
```

Channels of the object's assigned action with each key's `frame`, `value` and `interpolation`. Reads Blender 5.x slotted Actions through the assigned slot's channelbag and falls back to legacy actions; `api` in the result says which. `owner` is `"object"`, `"data"` (a light's energy, a camera's lens) or `"shape_keys"`.

### `blender_insert_keyframe`

```python
blender_insert_keyframe(
    object: str,
    data_path: str,
    frame: float,
    value: float | list[float] | bool | str | None = None,
    index: int = -1,
    overwrite: bool = False,
    interpolation: str | None = None,
    owner: str = "object",
    target_uuid: str | None = None,
    _timeout: float = 30,
) -> str
```

Sets the frame, then the value, then inserts the key. That order matters: setting a value and then changing frame re-evaluates the animation and silently discards the value. An existing key on the same channel and frame is **never replaced** unless `overwrite=True`, and replaced values come back in `replaced`, so an authored pose can't be destroyed by accident. Omit `value` to key the property's current value.

### `blender_set_interpolation`

```python
blender_set_interpolation(object: str, interpolation: str, data_path: str | None = None,
                          frames: list[float] | None = None, owner: str = "object",
                          target_uuid: str | None = None, _timeout: float = 30) -> str
```

Sets `CONSTANT`, `LINEAR`, `BEZIER` or any other Blender interpolation on the object's keys, optionally for one property and/or specific frames.

## Job-pump health

The addon reports its job queue about every 10 seconds from its network thread, so a report still arrives while Blender's main thread is busy. `blender_list_available_clients` shows it as `health` (`queue_depth`, `active_jobs` with `running_seconds`, `drain_timer_registered`, `last_drain_seconds_ago`, `reported_seconds_ago`), and a dispatch that times out or comes back `queued` includes it as `target_health`, with a hint that tells the three usual causes apart: Blender busy with a long job, a stalled job pump, or a dispatch that hasn't arrived yet.

### `blender_reset_pump`

```python
blender_reset_pump(target_uuid: str | None = None, bus_id: str | None = None) -> str
```

Restarts the addon's job pump over the bus, for the "connected, jobs queued, nothing running" stall that used to need a click on Disconnect and Connect in the sidebar. The request travels with the addon's next check-in (up to about 10 seconds) and runs on its network thread, so it works even when no dispatched command can. It can't help when Blender's main thread is busy with a long job; `health` in the reply shows which case you're in.

## Gates: how Tier-3 disablement works

<Aside type="caution">
Tier-3 gates are evaluated **addon-side**, not in the MCP tool. If a gated integration is off in the addon's preferences, the dispatch tool still runs to completion — the addon just returns `{"status": "failed", "error": "Unknown command type: <name>"}`. There's no client-side pre-filter.
</Aside>

The recommended pattern: probe with a Tier-2 status tool first, branch on the result. Example:

```python
status = json.loads(await client.call_tool("blender_get_polyhaven_status", {}))
if json.loads(status["result"]).get("enabled"):
    assets = await client.call_tool(
        "blender_search_polyhaven_assets", {"asset_type": "textures"}
    )
else:
    raise RuntimeError("PolyHaven disabled — enable in addon prefs")
```
